The model is `thinkingmachines/TML-d24-varloop-research`, where LOOP_COUNT is the number of passes through its looped middle layers (`loop_num_passes` in the model config). I ran LOOP_COUNT = 1 to 5 and, for comparison, the official `thinkingmachines/Inkling-2-Mini`, which makes 3 fixed passes. On 24 November 2026 I served them with vLLM in tensor parallel on two RTX 5070 Ti, one server and one [pi](https://github.com/earendil-works/pi) coding agent at a time. pi edits files and runs commands on its own until it decides it is done.

Each server gave its agent the longest context its key-value (KV) cache could hold. The context shrinks as LOOP_COUNT grows: 736,128 tokens at LOOP_COUNT = 1, 162,688 at LOOP_COUNT = 5. For Inkling 2 Mini it was 301,056 tokens.

Each agent ran in its own container, started and watched by a script. To test its work it could run `pagecheck`, which opens the page in headless Chromium with software WebGL, at noon and at midnight. It reports JavaScript errors, pictures that are blank, too dark or overexposed, whether the scene moves, whether lights come on at night, and whether dragging and the mouse wheel work.

pi stops when the model answers without calling a tool. If an agent stopped before a passing `pagecheck`, the harness reopened the same session with a fixed message asking it to continue, up to 6 times. Each agent had 90 minutes in the first step and 45 in the second, restarts included.

The time each agent took, from its start to the end of the final `pagecheck` that the harness ran on its page:
